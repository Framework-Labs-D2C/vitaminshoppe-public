03 — Fields

What a merchandiser fills in

Generated from _schema.ts, in the order Amplience shows them.

FieldTypeConstraintsDescription
showRating
Show rating pill		 boolean default true The outlined pill of five stars and the rating above the promo line. Switch it off and the panel closes up cleanly. It also stays hidden whenever the rating or the review count below is empty.
ratingValue
Overall rating		 string max 3
^[0-5](\.[0-9])?$		 The score in the pill, out of 5, e.g. "4.9". Type the number only — the module adds the "/5" and fills the stars from it. This is typed by hand and is not read from the review platform, so check it against the live figure before publishing. The pill only appears when both this and the review count are filled in.
reviewCount
Review count		 string max 12 How many reviews the score is based on, written exactly as you want it to read, e.g. "5,400+". The module adds the word "Reviews" after it, so do not type that. Like the rating, this is manual and not read from the review platform. The pill only appears when both this and the overall rating are filled in.
eyebrow
Pre-heading		 string max 40 A short promotional line above the headline, e.g. "Buy One, Get One". It prints exactly as you type it — unlike some modules this one does not uppercase it — in bold Lato one step smaller than the description. Keep it to a few words; it wraps at about 40 characters on a phone. Formatting: **bold**, _italic_, and ~12~ for subscript. A registered mark (®) is raised automatically, and a plain asterisk is never formatting. Leave empty to hide it.
heading
Heading		 string required max 60
min 1		 The headline, e.g. "Support Lean Muscle Growth. Recover Stronger." Wrap words in _underscores_ for italic and **double asterisks** for bold. Write ~12~ for subscript; a registered mark (®) is raised automatically, and a plain asterisk is never formatting. The panel grows to fit however many lines it takes, but every extra line pushes the button down — the design's 45 characters run to two lines on desktop and three on a phone. For an offer, keep it to two or three words such as "50% OFF" and pick the largest size below.
headingLevel
Heading level		 string h1 · h2 · h3
default "h1"		 A hero is usually the first thing on the page, so h1 is usually right here — but only if no other module on the page is also h1. Choose h2 when something above it already carries the h1. This changes nothing you can see: the size is set separately below.
headingSize
Heading size (desktop / mobile)		 string 64px / 38px · 56px / 34px · 48px / 30px · 36px / 24px · 28px / 20px · 20px / 16px
default "48px / 30px"		 A fixed pair from the TVS type scale — the first size applies from tablet up, the second on phones. 48px / 30px is the design for a copy headline. The largest pairs are for a short offer such as "50% OFF": at 64px a full sentence fills the panel and pushes the button below the fold on a phone. 20px / 16px is the same size as the description, so the headline stops standing out.
headingFont
Heading font		 string Lato · corisanderegular · Fields
default "Fields"		 Fields is the serif the copy-led design uses and is the default. It is not yet installed on vitaminshoppe.com, so until it is, the heading falls back to Georgia — still a serif, but not the exact drawn face. The offer design sets "50% OFF" in Lato, so pick Lato for an offer. This affects the headline only; the pre-heading, description and button always stay Lato.
body
Description		 string max 220 One or two sentences under the headline, 60 to 160 characters reads best — the design's 165 run to two lines on desktop and six on a phone. Wraps rather than truncating, and every extra line pushes the button down. Formatting: **bold**, _italic_, and ~12~ for subscript. A registered mark (®) is raised automatically, and a plain asterisk is never formatting, so a footnote marker like 20%* is safe. Leave empty to hide it.
image
Photo		 string required min 1 Full URL of the photograph, cropped to 4:3 before upload — the design is 756 × 567. jpg, jpeg or png. It fills the left half of the module on desktop and is cropped to fit, so keep the product near the centre. Product shots and decorative detail belong here — never text, which must stay real HTML so search and AI crawlers can read it.
imageAlt
Photo alt text		 string required min 1 Describe what the photograph shows, e.g. "BodyTech Elite Muscle Growth Peptide tub on a stack of weight plates". Required for accessibility. Do not write "image of" — a screen reader already says that. Also used for the phone crop unless you give that its own alt text below.
imageMobile
Photo (mobile)		 string max 500 Full URL of the phone crop, also 4:3 — the design is 375 × 281 — shown above the panel rather than beside it. Falls back to the desktop photograph when empty, which is fine when the product is centred: the shape is the same, only smaller.
imageAltMobile
Photo alt text (mobile)		 string max 300 Only needed when the phone crop shows something different. Leave empty to reuse the desktop alt text, which is also what happens if no mobile photograph is set.
backgroundColor
Panel background colour		 string The colour of the text panel beside the photo. White is the design; leave empty to keep it. If you change it, check it against the text colour below — the two are not checked for you, and a mid or dark colour under the navy text leaves the panel unreadable and fails the accessibility standard this page is held to.
textColor
Panel text colour		 string The colour of the pre-heading, headline, description and guarantee text. Navy #012169 is the design; leave empty to keep it. The button keeps its own colours, set below. Change this only together with the panel background, and only to a pair with strong contrast.
ctaLabel
Button label		 string required max 30
min 1		 The call to action, e.g. "Shop Now". It stretches the full width of the panel, so a short label reads best. Formatting: **bold**, _italic_, and ~12~ for subscript. A registered mark (®) is raised automatically, and a plain asterisk is never formatting.
ctaUrl
Button link		 string required max 500
min 1		 Where the button goes. To jump to a spot on this page, enter # followed by that module's Section ID — e.g. #buy-box scrolls to the Buy Box, whose Section ID must be filled in or the link does nothing. Use a relative path for vitaminshoppe.com destinations.
ctaStyle
Button colour		 string dark · light · outline
default "dark"		 Dark is #0458AD with white text and is the right choice almost every time, because the button sits on a white card. Light is white with #0458AD text and a thin #0458AD outline — it needs a dark surface behind it to be visible, so on the white card it reads as a weaker second choice rather than the main action. Outline is transparent with a black edge and black text, which also reads on the white card and is quieter still.
showGuarantee
Show guarantee row		 boolean default true The line under the button — a shield icon and short guarantee text between two thin rules. Switch it off and the spacing closes up cleanly. It also stays hidden whenever the guarantee text below is empty.
guaranteeText
Guarantee text		 string max 40 The words beside the shield, e.g. "30 Days Satisfaction Guarantee". Keep it to one short line — it does not wrap, and a long line squeezes the rules on either side to nothing. Formatting: **bold**, _italic_, and ~12~ for subscript. A registered mark (®) is raised automatically, and a plain asterisk is never formatting.
dividerColor
Guarantee divider colour		 string The colour of the two thin rules either side of the guarantee text. Light blue #41B6E6 is the design; leave empty to keep it.
priority
Prioritise image loading		 boolean default true Switch on when this hero is the first thing on the page, so the photo loads immediately instead of lazily.
sectionId
Section ID		 string max 50
^[a-z][a-z0-9-]*$		 A name for this specific hero, used for two things. A link anywhere on the site can jump straight to it by ending the URL with # and this name, e.g. #peptides-hero. Page-level CSS can also target this one hero rather than every hero of this type. Use lowercase letters, numbers and hyphens, start with a letter, and make it unique on the page — two modules sharing an ID will break the jump link. Leave empty if you need neither.

10 — Deviations

Deviations

Recorded as each was found while building, so the gaps are visible rather than forgotten.

Layout flips at 1024px, not 768px

Built stacked below lg, split from lg, Figma padding from xl

Figma draws 1512 and 375 only. Two 384px columns at 768 leave a 256px content track behind the panel's 64px padding, which starves a 48px heading (the Expert Module precedent in sections/CLAUDE.md § Breakpoint). So the photo stacks over the panel up to 1023px, the split starts at 1024 with 48px panel padding, and the drawn 64px arrives at 1280.

Rating pill is two fields, not one 20-45 character string

Built ratingValue + reviewCount, composed as 4.9/5 • 5,400+ Reviews

The FSD gives the row a Character Count of 20-45 and no field. The pill is built exactly as the Testimonials badge already is — a score and a count, composed in the markup — so the two modules share their vocabulary and a merchandiser fills the same two boxes on both. The stars are filled from the score. The toggle the FSD asks for is showRating; the pill also hides itself when either field is empty. Open comment 1 asks what the 20-45 was meant to count.

Pre-heading prints as typed

Built eyebrow, 40 characters, no uppercase

The shared eyebrow field is the FSD's Pre-heading. Its vocabulary description says it uppercases itself, which is true of the slim hero; here the design sets "Buy One, Get One" in title case, so the description is overridden and the markup carries no uppercase. Same precedent as the Bundle Module's label.

Photo is content imagery, not a background

Built image / imageAlt / imageMobile / imageAltMobile

The FSD's row is titled "Background", but 756 × 567 is half the frame beside the panel, not behind it, so the fields are the content-imagery quartet. One <picture> carries one alt, tracked to the crop on screen exactly as the slim hero does. Open comment 4 asks the client to confirm the reading.

Panel colours are colour pickers

Built backgroundColor and textColor, empty keeps the design

"Custom background color, text color" is built as two Amplience colour pickers, applied as --plx-hero-banner--background and --plx-hero-banner--text on the section root, so a page rule can retune one hero the same way. The stars, the shield icon and the pill border follow the text colour; the button keeps its own ctaStyle. Contrast is not checked for the merchandiser — both descriptions say so.

Guarantee icon is fixed

Built toggle, copy and divider colour are fields; the shield is not

The FSD lists copy and divider colour as editable, so guaranteeText and dividerColor are fields and showGuarantee is the toggle. The shield-tick is Figma's own path, inline and stroked in the text colour, and is not merchandisable — the FSD does not ask for it to be.

Offer headline at 96px / 64px

Not built on hold

Figma sets "50% OFF" at Lato 96 / 64 with line-height 1, with no token bound. The shared headingSize scale ends at 64 / 38 and is enum-locked across every section, so a hero-only value is a build error. Decision held 2026-08-26 pending team feedback; the direction going to the team is reinstating the merchandiser cssOverrides field (commit 56f3cdc, removed in 31eb90f), so one content item can carry --plx-font-size--heading: 96px without a scale change. Until then the offer variant builds at 64 / 38.

Analytics — impression (viewport entry)

Not built

Same position as the slim hero: no impression event name appears in any TVS template, so building one means inventing an event their handler ignores. Click tracking is built — raiseEvent('ItemClick', …, 'Hero Banner') and the GA4 promotion-click push with creative_slot: 'hero_banner'. Needs the impression name and payload from TVS.

Heading renders in Georgia until Fields is hosted

Not built waiting on the client

Fields is the drawn face and the default; it is not hosted on vitaminshoppe.com (base.css § heading font records the check), so the stack falls to Georgia, whose glyphs run about 10% wider. Measured 2026-08-26 against the frames: size and leading match exactly (58px pitch desktop, 36px mobile), but the desktop headline wraps to three lines where Figma has two, which makes the section 599px tall against the drawn 567 and lifts the pill off centre. It corrects itself the day the font is hosted; nothing in the markup is waiting on it.

Registered mark is raised

Built house rule

Figma sets the ® in the description inline at body size. Every prose field goes through richText, which raises a bare ® into a <sup> (root CLAUDE.md), so the two marks in the description sit small and high. The rule is deliberate and shared by every section; the frame is the outlier.

Tablet band: 3:2 photo, capped at 560px

Built md:aspect-[3/2] md:max-h-[560px], back to 4:3 at lg

Stacked at 768 the 4:3 crop is 576px tall, and at 1023 it is 767px — a full viewport of photograph before the headline, with the CTA below an iPad fold. Between 768 and 1023 the photo is cropped to 3:2 (11% off the height, safe for a centred product shot) and capped at 560px. Raised by the in-between review 2026-08-26.

Panel content capped at 680px and centred

Built max-w-[680px] mx-auto inside the panel

At 1920 the panel's content track is 832px, which stretches the button into an 832 × 49 bar and runs body copy to about 100 characters a line; between 768 and 1023 the stacked column runs to 943px the same way. The content block is capped at 680 and centred in the panel. The cap sits above the drawn 628, so at 1512 nothing changes, and 680 rather than 628 because the design's own headline wraps to a one-word third line at 628 in Georgia. Only bites past a 1616px viewport on desktop. Raised by the in-between review 2026-08-26.

Tablet button stays full width

Not built left for a design call

After the cap the stacked button is 680px wide between 768 and 1023. The review rated it taste rather than a defect: a full-width CTA is conventional for a stacked layout and the 50px height is an easy target. md:max-w-[400px] lg:max-w-none on the anchor is the fix if it is wanted.

Button is 49px tall, not 50

Not built shared component

The shared .button renders 16 × 1.1 + 2 × 16 = 49.6px and the browser rounds down. It is components/button.css, used by every section, so it is not changed here; a 1px correction belongs to the component.

Module reference

What each Platter module holds

12 modules, 173 merchandiser settings between them, and 9 GA4 events pushed from 22 places. Every field, event, value and file path below is read out of the schemas and the markup that ship, so this is an inventory of what is there rather than a summary of what was planned.

Each module names the file it lives in, lists the settings a merchandiser fills in, and prints every analytics payload it sends. Use it to fill in a content item, to build a GTM trigger, or to find the exact line in the exact file behind either.

01 — How to use this

How the events reach GTM, and how to see them

Each module creates window.dataLayer if it is not already there and pushes a plain object into it. GTM replays a pre-existing dataLayer when the container initialises, so an event pushed before the container loads still arrives; nothing depends on our script and TVS's tag loading in a particular order.

window.dataLayer = window.dataLayer || [];
window.dataLayer.push({ event: 'select_item', ecommerce: { … } });

To check any of this on a landing page, open GTM Preview, or read what has already fired straight from the console:

dataLayer.filter((entry) => entry.event)

Nothing else is involved. There is no gtag or ga call in any module — the dataLayer is the whole interface, and TVS's container decides what to do with what lands in it. No module reads the dataLayer back either, so no event depends on another tag having run first.

Finding a page and a module

Every module below names the file it is written in, relative to the component repository, and the method or Alpine attribute that pushes each event. Searching that file for the event name lands on the payload printed here. The landing pages themselves are on the QA storefront at qa1.vitaminshoppe.com/lp/<delivery key>, and each module's reference page lists the pages it renders on.

05 — How values are built

Two helpers, and where the list id comes from

Merchandisers write **bold**, _italic_ and ~12~ inside headings in Amplience. Sending a heading raw would put those marks into the reports, so every display value passes through one of these first.

HelperWhat it doesExample
plainText(value)Removes the merchandiser's formatting marks and returns what a shopper sees. The registered mark stays: it is content, not syntax.Why Customers Love _BodyTech_ Peptides → Why Customers Love BodyTech Peptides
handlize(value)The same, then lowercased, with every run of non-alphanumeric characters collapsed to a single underscore. Used for identifiers only.The Sports Peptides Spot → the_sports_peptides_spot

List identity

Each product module derives its item_list_id from its own heading and appends a suffix naming the module type, so two modules on one page never collide.

19 — Working with these events

What to know when you configure or test

Behaviour that affects what a report shows, or what to expect while testing a page.

Changing a heading in Amplience changes the list id

item_list_id and item_list_name are both derived from the module's heading. Renaming the heading renames the list, and a report grouped on it will show the old and new names as two lists from that day on. Rename during a reporting period only when you mean to.

Two modules of the same type on one page need different headings

The list id is the handlized heading plus a suffix for the module type, so two Product Carousels with the same heading produce the same item_list_id and their impressions merge. Template 1 carries three carousels; each has its own heading.

Impressions are one per page load

view_item_list fires the first time a module is half visible and does not fire again, so scrolling a module in and out of view does not inflate the count. Reload the page to see it again while testing.

A dataLayer push that throws is swallowed

Every push is wrapped, and a failure is written to the console as analytics: dataLayer push threw rather than raised. If events are missing on a page, check the console before assuming the module did not fire.

The container can load after the module

Each module creates window.dataLayer if it is absent and pushes into it, and GTM replays a pre-existing dataLayer on init. Events pushed before the container loads still arrive, so tag load order needs no coordination.

Prices and names come from TVS-Common, not from Amplience

item_name, item_brand, item_category and price are read from the product response at render time. A merchandiser cannot change them from the CMS, and a field the response omits arrives as an empty string or zero rather than missing.

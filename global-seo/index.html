03 — Fields

What a merchandiser fills in

Generated from _schema.ts, in the order Amplience shows them.

FieldTypeConstraintsDescription
breadcrumbs
Breadcrumb trail		 array The page's position in the site, from the homepage down, shown under the page title in Google results. List every step in order and leave the last step's link empty — the last step is this page itself. Leave the whole list empty to emit no breadcrumb.
skus
Products (SKU ids)		 array The products this page features, in the order you list them. Enter TVS SKU ids exactly as they appear on the product page, e.g. VS-4612. This list is invisible on the page: it tells search engines which product pages this page features, which helps them connect the page to those products. Leave empty to emit nothing.
videoName
Video title		 string max 120 Only fill the video fields when a video actually plays on this page. The title shoppers would know the video by. All three of title, thumbnail and video file link are needed before anything is emitted.
videoDescription
Video description		 string max 300 One or two sentences on what the video shows. Optional.
videoThumbnailUrl
Video thumbnail		 string max 500 Full URL of the video's poster image. jpg, jpeg or png.
videoContentUrl
Video file link		 string max 500 Full URL of the video file itself (the .mp4), not the page it plays on.
videoUploadDate
Video upload date		 string ^\d{4}-\d{2}-\d{2}$ The date the video was first published, as YYYY-MM-DD. Optional.
ogTitle
Share title		 string max 90 The title shown when this page is shared on social media or in chat apps. Leave empty to let the platform pick.
ogDescription
Share description		 string max 200 The one-to-two sentence preview text under the share title.
ogImage
Share image		 string max 500 Full URL of the preview image, at least 1200×630 for a large card. jpg, jpeg or png.
embeds
Page embeds		 array Third-party snippets that should run on this page — a feedback widget, an analytics tag, a partner pixel. Paste each snippet exactly as its vendor gives it to you, <script> tags and all, and give it a name so the list stays readable. Drag a row to reorder it. Snippets run in the order listed. Only <script>, <style>, <link> and <meta> are kept — anything else in a snippet is ignored. Leave the list empty on a normal page: everything here runs on every visit, so an unnecessary snippet is a slower page for every shopper.

05 — User requirement

User requirement

No shopper-visible behavior. The module exists for search engines, AI crawlers and link previews.

06 — Admin requirement

Admin requirement

  • All pages must include dedicated, editable fields for SEO Title and Meta Description tags.
  • Every landing page requires primary, page-level structured data (Schema markup) to define the page content.
  • Modular structured data (hybrid approach): high-value modules (Product, Review, FAQ, Video) must emit their own structured data; implement a clear hierarchy so it integrates with the primary page schema without conflicts; provide a switch per module to enable or disable its output.

07 — Other requirements

Other requirements

  • Content crawlability: modules must not be hidden; they must render as real HTML text and be exposed to crawlers.
  • The solution must leverage the existing Prerender setup.

08 — Deviations

Deviations

Per-module structured data and its toggles replaced by one page-level emitter

Built

This section is the single page-level emission point (BreadcrumbList, summary ItemList of featured products, VideoObject). Google retired FAQ and HowTo rich results in 2023, requires single-product pages for Product rich results, and treats markup for content not visible on the page as a manual-action trigger — so per-module emission with merchandiser toggles multiplies invalid states while earning nothing. Full evidence: docs/specs/2026-08-10-global-seo-design.md and docs/global-seo-client-note.md.

SEO title and meta description fields not duplicated here

Not built

cs-landing-page.seoTags already owns both fields and we already push them per page. A second source of truth in this section would drift from the first.

Prerender leverage extended to readiness signaling

Built

The FSD predates the observed blank-snapshot captures. This section sets prerenderReady false at injection and true once its payload is emitted, turning the snapshot moment from a network-idle guess into a signal.

The module itself is invisible

Built

The crawlability clause ("modules must not be hidden") governs content modules: copy must be real HTML text. This module renders no content at all — its output is head metadata, which is real markup in the served document. Nothing readable is hidden from anyone.
